### 收到 / 送出 怎么区分（本软件的取舍）

设计系统写死了「只有一个强调色，不存在第二个品牌色」，而账本必须区分方向。做法是：

- **方向的识别由「收到 / 送出」标签文字与金额正负号承担**，颜色只是辅助
- 收到 = Action Blue，送出 = 次级墨色 `#333333`
- **不新增第二个品牌色**

副作用是它比双色方案更可达：早先的绿/棕橙配色在红绿色盲下色差 ΔE 只有 4.0（安全线 8），换成现在这套后，识别根本不依赖颜色。

## 2. 字

字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text/Display", system-ui, "PingFang SC", sans-serif`。macOS/iOS 上直接落到真正的 SF Pro；不装字体文件（自包含底线）。

| 用途 | 字号 / 字重 / 行高 / 字距 | 落在哪 |
|---|---|---|
| 页面标题 ✅ | 40 / 600 / 1.1 / **−0.4px** | 软件名 |
| 深色面标题 | 28 / 600 / 1.14 / −0.28px | 荒诞层判词、弹层标题 |
| 大数字 | 34 / 600 / 1.2 / −0.374px | 总账四格 |
| 章节标题 | 21 / 600 / 1.19 / 0.231px | 录入 / 总账 / 关系人 / 明细 / 存档 |
| 副文案 | 21 / 400 | hero 那句「一本正经地给人情往来记账」 |
| **正文** ✅ | **17** / 400 / 1.47 / −0.374px | 输入框、按钮、弹层正文 |
| 次级 | 14 / 400 / 1.43 / −0.224px | 表格、chips、筛选、翻页 |
| 强调次级 | 14 / 600 | 表头 |
| 微文案 | 12 / 400 / −0.12px | 标签、脚注、改动列、页脚 |

**硬规矩**

- **正文 17px，不是 16px** ✅——这是这套系统的签名节奏
- **显示级字号一律负字距** ✅（≥17px 用 −0.12 ~ −0.4px），12px 及以下不用
- **字重梯度只有 300 / 400 / 600 / 700，没有 500** ✅
- 标题用 600，不用 700
- **所有数字用 `font-variant-numeric: tabular-nums`** ✅——账目要对得齐

## 4. 层次与阴影

**全系统零阴影** ✅。原系统只保留一个阴影，且只给产品照片用——本软件没有产品照片，所以一个都不该出现。

分层只靠三样：

1. **换面色**（白 ↔ 羊皮纸 ↔ 近黑）
2. **1px 发丝线**
3. **背景模糊**：弹层遮罩用 `backdrop-filter: blur(20px)` + 72% 羊皮纸

聚焦态用 `outline: 2px solid #0071e3` ✅，**不用 box-shadow**。

基数 8px。用到的档位：4 / 8 / 12 / 17 / 24 / 32 / 48。

## 6. 组件语法

- **主按钮**：Action Blue 填充 + 白字 + 胶囊 + `11px 22px`；按下 `transform: scale(0.95)`
- **次级按钮**：透明底 + 蓝字 + 1px 蓝边 + 胶囊
- **工具按钮**（存档、翻页）：珍珠白底 + 次级墨字 + 11px 圆角
- **行内动作**（改 / 作废）：纯文字蓝链接，不做成按钮——表格行才不会被按钮撑高
- **chips**：白底 + 发丝线 + 胶囊；**选中态是 2px `#0071e3` 描边**（内边距减 1px 抵消，避免跳动）
- **带删除叉的自定义 chip**：`标签 + ×` 拼成一个胶囊，**边框整圈画在外层容器上，两个子元素一律不画边** ✅——各画半边会在 hover 时两半颜色对不上、接缝外露
- **输入框**：白底 + `rgba(0,0,0,0.08)` 边 + 胶囊 + 44px 高
- **表格**：白卡包裹，表头 14/600 弱墨色 + 底部发丝线，行间软分隔，最后一行无线
- **页签**：胶囊，未选中 = 白底 + 发丝线，**选中 = Action Blue 实心 + 白字**；一次只显示一个视图，切换改 URL hash（`#/overview|rows|people|faq`），非法 hash 回落总览
- **录入区常驻**：不属于任何视图，永远在页签之上——办事现场不能为了录一笔先切页签
- **顶部品牌条**：48px 高、贴顶横贯整宽，**这是本软件唯一不按本规范、而按站点视觉走的部件**（近黑 `#0b0b0b` 底、发丝线 `#ffffff14`、等宽 12px 小字、酸绿 `#c7ff3d` 悬停）。左侧蘑菇 logo + Vibe everyting（回站点首页）与「作品墙」，右侧分享按钮。**logo 必须是本地副本**，断网与 `file://` 下也要显示（ADR-0005 修正）
- **测算向导**：四步进度条（3px 细条，走过的段落用 Action Blue）；每步一个大问题（28px/600）+ 一句说明；选项用 chips，**选中态 2px 描边**
- **测算结果三挡**：三张等宽卡片并排，**默认高亮「公允」**（2px Action Blue 边框 + 蓝色数字）——多花钱的选择权交给用户，系统不劝；金额一律**区间**，不给单点
- **免责块**：珍珠白底 + 软分隔线，12px 弱墨色公文腔长句，落款一句 14px 次级墨色把决定权交回用户
- **FAQ 条目**：18px 圆角白卡 + 发丝线，原生 `<details>` 折叠（零 JS），`+ / −` 指示；标题右侧挂两个 12px 胶囊标签——**「各地不同」用 Action Blue 描边**（提醒这条有地域差异），分类标签用珍珠白中性
- **民俗软提示**：录入区 12px 弱墨色，一条一行，**永远只提示不拦截**；末尾固定一句「以上为通行说法，各地风俗不同，仅供参考」
- **信用评级徽章**：胶囊 + 发丝线，12px；`AAA/AA` 用 Action Blue 描边与字，`CCC` 用弱墨色 + 珍珠白底，中间三档中性——**只有两端着色，中间不喧宾夺主**
- **当日小结**：录入区右下角一行 14px 弱墨色，只在今天录过才出现；撤销后原地变成「已撤销：XXX ¥N」

## 7. 图表

图表只出现在**总览**视图，三张：谁欠谁（发散横条）、逐年人情流水（分组柱）、关系板块（横条）。零依赖手写 SVG，不引图表库。

| 规则 | 做法 |
|---|---|
| 系列配色 | 收到 = Action Blue `#0066cc`；**送出 = 弱墨色 `#7a7a7a`** |
| **为什么图表的「送出」和表格不同色** | 表格里送出是**文字**用近黑 `#333`；图表是**大面积填充**，近黑会显得又重又脏。大面积填充比文字浅一档，这是刻意的 |
| 图例 | 两个系列以上必须有图例，识别不能只靠颜色 |
| 标注 | 每根柱子直接标数值，不靠鼠标悬停才知道 |
| 悬停 | 有 tooltip（近黑底 + 白字 + 8px 圆角），补充明细 |
| 网格与轴 | 极弱：网格线用软分隔色，零轴用发丝线，轴标签 11px 弱墨色 |
| 数据端 | 4px 圆角，基线端方角 |
| 单侧收敛 | 「谁欠谁」全部同号时自动收成单侧，不白占半张图 |

### 8.2 一纸人情资产负债表（长图）

配色照本规范：羊皮纸底 + 白卡头 + 发丝线分隔，**全图只有一处 Action Blue**（净额那个数字，以及评级里非 CCC 的档位）。字体用 PingFang SC。含编号（`RQ-XXXXXX`）、签发日期、判词、三个大数、主要指标、信用评级垫底三名、免责小字与出处。

### 8.3 导出物（Excel）

导出的 `.xlsx` 也按本规范排版——它是软件的一部分，不该是一坨默认样式的裸表格。

| 规范条目 | 在 Excel 里怎么落 |
|---|---|
| 强调色表头 ✅ | 表头行 Action Blue `#0066CC` 填充 + 白色加粗字 |
| 发丝线 ✅ | 每个数据行下 1px `thin` 边框，色 `#E0E0E0`（对应界面里的行分隔） |
| 收 / 送同色规则 ✅ | 收到金额 `#0066CC`，送出金额 `#333333`；净额按正负取这两色 |
| 数字对齐 ✅ | 金额列右对齐 + 数字格式 `¥#,##0`（Excel 数字本身等宽） |
| 次级信息弱化 | 大写、日期、改动列用弱墨色 `#7A7A7A` |
| 作废行 ✅ | 删除线 + 弱墨色，和界面一致 |
| 留白 | 表头行高 24pt、数据行 20pt，列宽逐列调过 |
| 便于使用 | 表头带自动筛选；两个工作表「人情往来」「关系人汇总」 |

**字体替换**：SF Pro 在 Excel 里不存在，中文用 **PingFang SC**（SF Pro 的中文伴侣字体），字号 11pt。

**做不到的**：冻结表头——我们用的 `xlsx-js-style`（Apache-2.0，写样式用）不支持写冻结窗格，实测 `!freeze` / `!views` 都不生效。想要就得换库或后处理，暂不做。

## 10. 测算的算法与免责（口径写死在这里）

这是全系统**唯一会影响用户真实花钱**的功能，所以口径必须可解释、可复核。

| 情形 | 口径 | 下限取自 |
|---|---|---|
| 他随过我 | **对等回礼** | 他最近随我的那一笔 |
| 新人 + 该关系板块有记录 | **同侪基准** | 该板块我历史送出的**中位数**（偶数样本取两中位平均，取上中位会系统性偏高） |
| 新人 + 板块无记录 + 填了起步价 | **当地起步价** | 用户自己填的数 |
| 以上都没有 | **明说给不出** | 不编数字，改建议「问一个跟你关系相当、也去的人」 |

- **三挡区间**：保守 `[base档, +1]`、公允 `[+1, +2]`、排面 `[+2, +3]`；撞到档位表顶端时写「¥X 起」
- **通胀不进建议值**：只在查到旧记录时按 `5%/年` 给一句折算提醒，并**写明比例是本系统假定的**
- **民俗**：建议区间**自动剔掉含 4 的档位**（几乎无争议）；红白事双单数**只提示不改数**（争议大）
- **同侪对照**：走对等回礼时，若该板块中位数 ≥ 下限 ×1.5，把对照摆出来——数字不改，但差距要让用户看见
- **档位表可改**（默认 `100/200/300/400/500/600/800/1000/1500/2000/3000/5000`），地域差异太大，写死等于逼人不用

**能解释的算法才敢给建议**：不做亲疏系数、场合系数、地域系数这类我们编出来的权重——用户没法验证的东西不该参与定价。

## 11. 明确不做

- 装饰性渐变
- 卡片 / 按钮 / 文字的任何阴影
- 第二个品牌色
- 字重 500
- 图片圆角出现在非卡片语境
- 编造的系数、权重、行情数据参与建议金额的计算
